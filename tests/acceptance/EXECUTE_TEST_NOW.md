# Run the local proposal demo

Follow the [demo guide](../../SIMPLE_TEST_GUIDE.md) to launch Streamlit and load the fictional Acme transcript under **Proposals → Generation Controls → Demo Mode**. The [testing guide](../../PLATFORM_READY_FOR_TESTING.md) lists the manual checks. Complete this record for the version you actually ran.

| Check | What to record |
| --- | --- |
| Input | App version, model or demo mode, sample transcript and documents requested |
| Generation | Which drafts appeared, errors, and whether the run used a live provider or mock data |
| Review | Source facts checked, unsupported commitments, corrections and reviewer decision |
| Storage | Which project and documents remained visible after reopening |
| Export | Files inside the ZIP and any differences from the reviewed drafts |

Record each step as passed, failed or untested. Preserve errors even when the interface displays a success message.

## Measuring effort

A demo run can show whether the workflow is usable. To assess time or cost, follow the [paired comparison scenarios](business_value.feature). Record drafting, review and correction time for each method and the same brief. Include unsuccessful runs and model costs. A missing manual baseline leaves time savings unmeasured.
